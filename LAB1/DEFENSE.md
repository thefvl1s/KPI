# DEFENSE - Завдання 1: Домен і модель даних (ER)

**Намір і критерії:**
Побудувати концептуальну ER-модель для інтернет-магазину книг. Головні критерії: узгодженість типів, коректне найменування сутностей та виділення асоціативної сутності `OrderItem` для фіксації історичної ціни.

**Топ-3 розбіжності (spec ↔ артефакт) + коміт-виправлення:**
1. *Розбіжність:* (Аудит атрибутів та нормалізації) У згенерованій моделі для замовлення (Order) був відсутній атрибут загальної суми чека.
   *Виправлення:* Додано атрибут `total_amount` до `spec.md`, модель перегенерована. (Коміт: `update spec to add total_amount to Order`)
2. *Розбіжність:* (Аудит ключів та типів проти spec.md) ШІ самостійно обрав тип `float` для грошових полів, що є помилкою для фінансових БД.
   *Виправлення:* Зафіксовано вимогу в `spec.md` щодо використання типу `DECIMAL`. (Коміт: `enforce DECIMAL type for money values in spec`)
3. *Розбіжність:* (Аудит найменувань) ШІ згенерував назви сутностей у верхньому регістрі (напр., `ORDER_ITEM`), що порушує конвенцію найменування.
   *Виправлення:* Додано критерій щодо використання `PascalCase` для всіх сутностей. (Коміт: `enforce PascalCase for entity names in spec`)

*Посилання на чат з Gemeni: https://share.gemini.google/1PkxruhkIy2t*

**Ключові рішення (ADR):**
Усі ключові рішення (зокрема щодо фіксації ціни в `OrderItem` та нульової кардинальності зв'язку Автора з Книгою) винесено в окрему папку `adr/` та детально оформлено за стандартом MADR (з описом розглянутих альтернатив, їхніх переваг та недоліків).

**Перевірка - узгодженість із попередньою моделлю (як перевірив):**
Перевірив згенерований ШІ рендер Mermaid проти `spec.md`. Переконався, що всі атрибути, типи та регістр на діаграмі збігаються з текстом специфікації. Усі виправлення робилися виключно через оновлення `spec.md`.

Після отримання зворотного зв'язку від викладача було виконано ручне доопрацювання моделі та документації:
1. **Кардинальність:** Виправлено розбіжність між специфікацією та діаграмою. Зв'язок "Автор-Книга" змінено на опціональний з обох боків (`}o--o{`), що дозволяє системі підтримувати "народну творчість" (книги без авторів) та створювати профіль автора до появи його книг на складі.
