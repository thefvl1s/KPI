# MADR 0003: Моделювання Use Cases та меж системи

**Status:** Accepted

**Decision Drivers (Чинники рішення):**
- Необхідність уникнення дублювання між EARS, User Stories та діаграмою.
- Вимоги до автоматизації тестування (BDD) через Gherkin.
- Заборона моделювання технічних деталей (як-от інтеграція шлюзу) як окремих Use Cases.

**Decision (Рішення):**
1. Об'єднати User Stories та Gherkin-сценарії в єдиний артефакт.
2. Виключити Платіжну систему з переліку Акторів, оскільки вона є деталлю реалізації (наслідок), а не ініціатором взаємодії. Дії "Розрахунок вартості" та "Обробка платежу" визнати внутрішніми системними кроками, які покриваються функціональними вимогами (EARS), а не відображаються як окремі овали на діаграмі.

**Consequences (Наслідки):**
- *Позитивні:* Діаграма Use Cases стала чистою та відображає виключно бізнес-цінність для користувача. Gherkin сценарії стали єдиним джерелом правди для тестувальників.
- *Негативні:* Вимоги до інтеграції зі шлюзом не візуалізовані на високорівневій схемі та потребують детального читання тексту EARS.
